- Se eliminan visualmente las portadas, manifiestos, estadísticas y bloques territoriales duplicados de la interfaz pública anterior.
- El header conduce a la experiencia 3.20, no a capas antiguas.
- El footer público duplicado se oculta para evitar dos cierres de página.

- Se conserva la distinción DOCUMENTADO / REFERENCIA / PENDIENTE.

### Regla de longitud
**La complejidad no se mide por cuánto se desplaza una persona.** Se mide por cuánto puede hacer el sistema detrás de una interfaz corta.

# REFORMULACIÓN TRONCAL · LEY MUNDIAL 3.20

## Identidad del proyecto

**OCARINA WILD es un proyecto serio de conocimiento territorial y biodiversidad.** Su prioridad es trabajar con información oficial, real, identificable y verificable; representar el territorio de manera honesta; y convertir esa información en una experiencia digital atractiva, sencilla y multidispositivo.

## Ley mundial 40 / 60 / 100

> **40% VISUAL · 60% TEXTO · 100% INTERACCIÓN SENCILLA**

Estos porcentajes son una **referencia editorial de composición**, no una obligación matemática de cada pantalla.

### 40% VISUAL

El frente debe tener presencia visual: fotografía documental cuando exista y pueda usarse, ilustración identificada como ilustración, mapas, territorio, color, tipografía, diagramas, iconos, audio o video cuando aporten sentido.

La imagen no debe decorar sin propósito. Debe ayudar a **ver, reconocer, comparar, recordar o comprender**.

### 60% TEXTO

El proyecto debe explicar. No alcanza con una galería bonita.

Cada contenido relevante debe poder responder, con el nivel de profundidad necesario:

- qué es;
- dónde corresponde;
- cuándo fue registrado o publicado;
- qué evidencia existe;
- quién lo documentó;
- qué fuente lo sostiene;
- qué parte es segura;
- qué parte es referencia;
- qué parte todavía está pendiente.

### 100% INTERACCIÓN SENCILLA

Toda la potencia del sistema queda detrás de acciones simples:

**tocar · elegir · buscar · abrir · comparar · escuchar · mirar · volver**.

El usuario no debe aprender el sistema para utilizarlo.

## Representación real

OCARINA WILD distingue estrictamente entre:

- fotografía documental local;
- fotografía de referencia;
- ilustración original;
- mapa o representación cartográfica;
- gráfico o visualización de datos;
- recreación o recurso artístico.

Nunca se presenta una representación como evidencia de algo que no demuestra.

Cuando una imagen no es local, debe decirlo. Cuando una ilustración no es documental, debe decirlo. Cuando una fotografía representa otra región, no puede utilizarse para insinuar presencia en San Patricio del Chañar.

## Sistema de fondo

El proyecto puede ser técnicamente complejo y contener muchas relaciones internas:

**FUENTE → RECURSO → EVIDENCIA → REGISTRO → TAXONOMÍA → TERRITORIO → MEDIA → REVISIÓN → RELATO**

Pero esa complejidad no debe aparecer como un panel administrativo para el visitante.

El sistema trabaja detrás. La experiencia muestra el resultado.

Para los registros de biodiversidad, OCARINA WILD toma como referencia estructuras de calidad como Darwin Core/GBIF: identificador de ocurrencia, tipo de registro, nombre científico, fecha, ubicación y otros metadatos de calidad cuando estén disponibles. citeturn0search0turn0search1

## Diseño multidispositivo

La experiencia se diseña primero para interacción táctil y se adapta a:

**320 px → 390 px → 680 px → tablet → notebook → escritorio → pantalla grande.**

La función no puede depender de hover, precisión del mouse o una pantalla grande. WCAG 2.2 se adopta como referencia para una experiencia perceptible, operable, comprensible y robusta. citeturn0search4turn0search6

## Regla de simplicidad

**Mucho sistema atrás. Mucha simplicidad adelante.**

El visitante no ve veinte herramientas. Ve pocas decisiones claras.

La profundidad aparece cuando la persona quiere profundizar.

## Regla de diseño

**Colorido al frente. Rigor atrás.**

El proyecto puede ser expresivo, visual, cálido y territorial sin perder seriedad documental.

La estética no debe falsificar la realidad ni competir con la lectura.

## Regla de fuentes

Las fuentes son parte del contenido, no una webgrafía.

El proyecto debe mostrar internamente el contexto necesario de cada fuente: institución, autor cuando corresponda, fecha, escala, función, crédito y relación con el contenido. Los enlaces externos pueden existir como trazabilidad técnica, pero la comprensión principal debe producirse dentro de OCARINA WILD.

## Regla de crecimiento

No se agregan módulos simplemente porque sean posibles.

Cada nueva función debe responder a una necesidad real y entrar en una arquitectura ya conectada.

**Más funciones no significa mejor proyecto. Mejor conexión significa mejor proyecto.**

## Frase troncal

> **SERIO EN LA INFORMACIÓN. REAL EN LA REPRESENTACIÓN. SIMPLE EN EL USO. PROFUNDO EN EL SISTEMA. VISUAL AL FRENTE.**
