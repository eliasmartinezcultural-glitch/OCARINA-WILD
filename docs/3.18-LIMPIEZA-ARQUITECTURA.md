# OCARINA WILD 3.18 · LIMPIEZA ARQUITECTÓNICA

Estado: ACTIVA
Fecha: 2026-09-30
Principio: mucho sistema detrás, poca fricción delante.

## Objetivo

3.18 no agrega otra capa visual. Hace lo contrario: elimina la exposición simultánea de capas que empezaron a superponerse durante 3.17.

### Problemas corregidos

- Se elimina de la vista pública la cadena de paneles PL1 + PL1 Deep + Inventario + Ley Visual como bloques consecutivos.
- Se elimina la repetición de estadísticas, reglas, fuentes y explicaciones.
- Se conserva el motor principal y el catálogo base.
- Se conserva la arquitectura de datos, fuentes, evidencia, reglas y esquemas de 3.17.
- La investigación queda detrás de una única puerta: CENTRO DE ARCHIVO.
- Las fuentes se consultan dentro de una única vista y con búsqueda.
- La profundidad es progresiva: catálogo → centro → fuente.
- No se depende de hover.
- La experiencia funciona con toque, mouse y teclado.
- No se crean datos nuevos ni se transforma una referencia regional en presencia local.

## Regla 3.18

Si una función puede vivir detrás de una acción clara, no ocupa espacio permanente en la vista pública.

## Arquitectura

CATÁLOGO → CENTRO DE ARCHIVO → ESTADO / FUENTES / REGLAS / DATOS

El centro consume las capas de datos existentes sin duplicarlas en el DOM público.

## Congelado

PL1, motor, catálogo base y ley visual permanecen como referencia/versionado. La limpieza cambia la exposición pública, no el contenido metodológico.

## QA

- 320 px: sin desborde horizontal.
- 390 px: controles táctiles utilizables.
- 680 px: composición intermedia sin duplicación.
- escritorio: una sola jerarquía principal.
- teclado: foco visible y cierre de diálogo.
- movimiento reducido: sin dependencia de animación.
- ningún botón sin acción.
- ninguna fuente sin destino.
- ninguna capa técnica obligatoria para el visitante.

## Resultado esperado

OCARINA WILD debe sentirse corto, claro y vivo, mientras mantiene por debajo un archivo cada vez más serio, trazable y ampliable.
